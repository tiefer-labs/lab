Status: in development. Owner: Tiefer. Licence: MPL 2.0.

## 2. Roles per split

A dataset has exactly one role per experiment. The test split is read only with `--final`, and every such read is logged where it runs.

| Split | Roles | Never used for | Where |
| :--- | :---: | :---: | :---: |
| train | training, normalisation statistics, class weights (L1), INT8 calibration | selection or scoring | `src/tiefer_lab/data/build_cache.py`, `src/tiefer_lab/train.py`, `src/tiefer_lab/quantise.py` |
| validation | selection of models and settings, the product decision, tuning of the baseline thresholds, early stopping and `best.pt` | training | `src/tiefer_lab/baselines.py`, `src/tiefer_lab/train.py` |
| test | final evaluation only | any selection or tuning | `src/tiefer_lab/evaluate.py` (`--final`) |

No test evaluation is logged yet; `reports/test_log.md` has no entries.

The test split is independent of the training patches, not of the dataset: it shares the labelling protocol, the sensor and the processing level. A result on it says nothing about other sensors ([RESULTS.md](RESULTS.md), section 18).

## 3. Harmonisation

Rules for making another dataset's labels and images comparable to the four classes of this repository. They apply once a candidate is used.

- **Classes:** each source class maps to clear (0), thick cloud (1), thin cloud (2), cloud shadow (3) or unlabelled (255). A source that does not separate thick and thin cloud is scored on the cloud problem only (binary metrics, section 4); a source without shadow is not scored on shadow. The reference masks of the extra variant follow the same rule (`MaskEncoding` in `src/tiefer_lab/data/source.py`).
- **Unlabelled pixels:** fill values, no-data and unlabelled pixels map to 255 and are left out of every metric.
- **Bands:** a band is used only when its centre wavelength and width are checked against the sensor's documentation and match a Sentinel-2 band; all other bands are unavailable, and the band-flexible model runs with the band set that remains. The numeric tolerance is an open fact (below).
- **Values:** top-of-atmosphere reflectance with the scale and offset from the sensor's documentation; a source given only in digital numbers or surface reflectance is not used until its conversion is checked.
- **Resolution:** frames are resampled to 10 m before inference and the mask back to the frame's size (`tiefer_lab.onboard.predict_frame`).

| Open fact | What resolves it | Where it is used |
| :--- | :---: | :---: |
| Numeric tolerance for naming another sensor's band after a Sentinel-2 band (centre wavelength and width) | a decision recorded in [ASSUMPTIONS.md](ASSUMPTIONS.md), checked on the first cross-sensor dataset | band matching of every candidate |

## 4. Metrics for comparison with published results

The CloudSEN12 paper reports per-patch accuracies of binary problems (CloudSEN12, Scientific Data, 2022, https://doi.org/10.1038/s41597-022-01878-2, Table 6 and the text that defines it, accessed 7 October 2026). This repository reports the same kind of numbers next to its own four-class metrics. TP, TN, FP and FN are the true positives, true negatives, false positives and false negatives of a patch.

| Metric | Definition in this repository | The paper's definition |
| :--- | :---: | :---: |
| Balanced overall accuracy (BOA) | (TP / (TP + FN) + TN / (TN + FP)) / 2 per patch, median over patches | the same formula and the same median |
| Producer's accuracy (PA) | TP / (TP + FN) per patch, median over patches | the same formula per patch, set to NaN on cloudless patches; summarised as the share of patches below 0.1, between 0.1 and 0.9 and above 0.9, not as a median |
| User's accuracy (UA) | TP / (TP + FP) per patch, median over patches | as for PA |
| Overall accuracy (OA) | (TP + TN) / all valid pixels per patch, median over patches | not used in Table 6 |

The cloud problem is thick plus thin cloud against the rest, as in the paper; the shadow problem is cloud shadow against the rest (`src/tiefer_lab/binary_metrics.py`). Only BOA is therefore comparable with the paper's summaries. Published values of other systems appear only in [LANDSCAPE.md](LANDSCAPE.md), in columns labelled "published" with their source; they are never placed in [RESULTS.md](RESULTS.md) or in any table of this repository's own measurements. How varied each built split is (class shares, cloud cover bins, shadow) is reported by `python -m tiefer_lab.data.richness` ([DATA.md](DATA.md), section 12).
